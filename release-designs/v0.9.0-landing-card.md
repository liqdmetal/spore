# v0.9.0 Landing Card — E2 pointers land on Base (the deployment release)

**The goal, verbatim from ROADMAP:** `spore msg send-e2 -to 0x…` works
end-to-end on a real EVM chain through a deployed `MyceliumMailbox`, with
compost-on-delivery proven on that chain — the EVM carrier row flips from
"live-verified (local Anvil); deployment pending" to
"**live, deployment receipt published**".

**The honest framing:** everything hard is already built, tested, and
byte-pinned (v0.8.0 was "everything the deployment needs except the funded
key itself"). v0.9.0 is an *execution* release: fund a key, run the deploy
command that already exists, prove the Anvil arc on a real chain, publish
the receipt, ship the default address.

---

## What is already in-repo (no new engineering required)

- **The contract:** `contracts/MyceliumMailbox.sol` — per-recipient sequenced
  inbox, `Inbox(to,from,seq,cid)` log for cheap `eth_getLogs` discovery
  (no full block scan), recipient-only `read`/`burn`. Stores opaque pointer
  bytes only; never holds a key.
- **The backend wiring:** `internal/evm/mailbox.go` — deliver/log-decode/
  read/burn wired through `chain.Watch` auto-burn (burn failure never fails
  a delivery). Anvil-proven end to end, including the post-burn empty-slot
  compost proof (`internal/evm/mailbox_live_test.go` — "COMPOST VERIFIED").
- **The deploy path:** `spore contract deploy-mycelium` — self-contained
  EIP-155 creation tx (hand-rolled over btcec, pinned byte-for-byte against
  go-ethereum vectors), then `eth_getCode` verification before printing the
  address. Key from `SPORE_EVM_PRIVATE_KEY` (preferred) or `-private-key`.
- **The bytecode guarantee:** `tools/mycelium.bin` is pinned solc v0.8.26
  output, held in place by three tests — no supply-chain gap between "what
  was audited" and "what gets deployed". (This is also why zk rollups are
  ruled out: pinned bytecode needs full EVM equivalence.)
- **The config seam:** `evm_mailbox` per-chain default already exists
  (`config.go` EVMMailbox + `mailboxContractOrDefault`: explicit flag wins,
  never leaks into the URL-flavored `-mailbox` of prekeybatch/invite;
  `spore init -mailbox-contract` writes it). v0.9.0 fills it with the real
  address.

## Chain decision (LIVE_NODES §3, 2026-09): Base first

- Base mainnet: chain 8453, RPC `https://mainnet.base.org`; testnet:
  Base Sepolia, chain 84532, RPC `https://sepolia.base.org`; explorers
  basescan.org / sepolia.basescan.org.
- Fee reality: avg ≈ $0.01/pointer tx (Token Terminal, 2026-09) — but the
  runbook rule is **measure with `eth_gasPrice` at run time**, never trust
  a doc number. Compost is the recipient's gas: `burn(to,seq)` costs a real
  (small) fee per message, unlike DERO's native expiry.
- Runner-up: Arbitrum One. Ruled out: Polygon PoS (different security
  story), zk rollups (pinned-bytecode risk), Ethereum L1 (dollars per
  message at pointer volume).

## The landing sequence — funding → receipt

### Phase A — rehearsal on Base Sepolia (free, do first)

One command does all of it (shipped post-v0.8.0):
`scripts/sepolia_rehearsal.sh` — estimate, deploy, the two-party proof
through a pair of loopback proxies, the empty-slot assertion, and
paste-ready LIVE_NODES §3 receipt lines. It needs TWO funded faucet keys
(`SPORE_EVM_PRIVATE_KEY` + `SPORE_EVM_PRIVATE_KEY_B`) — the recipient's
proxy signs the burn. The manual equivalent:
2. Fund from a Base Sepolia faucet (Alchemy or Chainlink run ones). Deploy
   plus a dozen deliver/burn rounds cost well under 0.01 testnet ETH.
3. Deploy: `spore contract deploy-mycelium -rpc https://sepolia.base.org -wait 5m`
   — pass `-wait 5m`: L2 sequencing to code-visible state can outpace the
   default 2-minute poll. Records address + creation txid (code verified
   first).
4. Two-party proof (the Anvil arc, now on a real chain). Sends sign
   node-side, so both endpoints run the loopback signing proxy in front of
   the same public RPC:
   - `spore evm-proxy -rpc https://sepolia.base.org -listen 127.0.0.1:8555` (A)
     and `:8556` (B)
   - sender: `spore msg send-e2 -to 0xB… -mailbox 0x<addr> -rpc http://127.0.0.1:8555 -from 0xA…`
   - recipient: `spore msg recv-e2 -mailbox 0x<addr> -rpc http://127.0.0.1:8556 -from 0xB…`
     (auto-burn is the default — no flag needed)
   - assert compost on-chain: `length(to)` unchanged after the burn and
     `read()` returning empty (mirrors the Anvil proof).
5. Record txids (creation, one deliver, one burn).

### Phase B — Base mainnet (chain 8453)

1. Fund a **dedicated** spore key with a small ETH amount. Measure first —
   the math is now one command (`spore contract estimate`, shipped after
   v0.8.0): run it with `-from 0x<deployer>` before deploying for the
   deploy row, and again with `-mailbox 0x<addr>` after deployment for
   deliver/burn rows plus the N-round funding total. The burn row is a
   labeled conservative constant when the node refuses an empty-slot
   estimate. Cents per message at 2026 fee levels, but measure, don't
   assume.
2. `spore contract deploy-mycelium -rpc https://mainnet.base.org -wait 5m`
3. Repeat the two-party proof against mainnet with tiny real amounts.
4. Publish (see the receipt block below) and flip the docs.

## Deliberately out of scope

- **Cross-chain identity proof** — its own later gate (roadmap item #10);
  EVM delivery here is DERO-independent (recipient is an EVM address,
  ratchet is X3DH as today).
- **Pay-with-message through the contract path** — stretch goal, not the
  gate; needs a payable `deliver` variant or value-forwarding pattern.
