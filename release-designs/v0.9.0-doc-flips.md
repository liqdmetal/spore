## Line-wrap constraints (verified by the 2026-10-06 dry run)

`TestReleasePrepProseDrainedAfterFlip` matches every required claim with
`strings.Contains` against the raw file text, so **a required claim must appear
as one contiguous run of characters — including across whatever line breaks you
choose.** A sentence wrapped naturally in the middle of a claim fails the gate.
Rehearsing this patch (registry entry + all 14 flipped surfaces) on a throwaway
branch found three claims a first-pass wrap had split; all three are in
`ROADMAP.md`:

| File | Claim that must stay on ONE physical line |
|---|---|
| `ROADMAP.md` | the Base address later shipped in v0.9.0 |
| `ROADMAP.md` | the shipped Base config default selects |
| `ROADMAP.md` | The Base deployment, two-party proof, and receipt-backed default shipped in v0.9.0; their canonical evidence is in |

In each case the fix is to move the whole claim onto one line — e.g. begin the
line at `the Base address…` rather than ending a line at `shipped`. Line length
is not gated; a long line is correct, a wrapped claim is not.

One claim is the opposite case — it *requires* a specific break. In `ROADMAP.md`
the fee-notes sentence must contain a newline followed by exactly three spaces:

```
Fee and limit notes are documented separately in
   the v0.9.0 fee-notes patch using deployment-day estimator output.
```

Leading whitespace is otherwise irrelevant, but a two-space or four-space
continuation fails it.

**How to check without waiting for the test.** Grep each required claim
directly; a `0` is a wrap bug:

```bash
grep -cF 'the Base address later shipped in v0.9.0' ROADMAP.md
grep -cF 'the shipped Base config default selects' ROADMAP.md
```

**The referee is self-describing.** `TestReleasePrepProseDrainedAfterFlip`
prints each missing or stale claim verbatim, so the loop after every edit is:

```bash
go test ./internal/evm ./cmd/spore -count=1
```
