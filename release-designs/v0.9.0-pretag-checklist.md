# v0.9.0 — pre-tag checklist

**TEMPLATE — NOT RUN.** The Base deployment and two-party mainnet proof have
not happened; do not tag until every deployment gate below is satisfied.
The runbook is canonical in `docs/LIVE_NODES.md` §3. This checklist mirrors
the shipped v0.8.0 pre-tag checklist and links the ready-to-apply drafts in
`release-designs/` (workspace root, outside the repo).

## 0. Decide and prove first

- [ ] **Chain:** Base mainnet, chain 8453, RPC `https://mainnet.base.org`;
      if the chain changes, update the title, receipt, RPC, fee measurement,
      registry key, doc patches, and tag body together (Arbitrum One is the
      documented runner-up in LIVE_NODES §3).
- [ ] **Base Sepolia rehearsal:** run `scripts/sepolia_rehearsal.sh` against
      the real `https://sepolia.base.org` with two faucet-funded keys. Record
      real rehearsal receipt values if completed. Its `--self-check` mode runs
      the same burn-recovery step and receipt line against a throwaway local
      anvil (no keys), and the pre-push gate runs that on every push, so the
      unfunded half of the path is never first executed on release day. The hermetic stub-chain CI
      run is not a real-chain receipt and supplies no Base fee measurement.
- [ ] **Base deployment + two-party proof:** deploy the pinned
      `MyceliumMailbox`, verify deployed code, then prove A → B `send-e2` →
      receive → auto-burn → empty-slot read on Base mainnet. Use funded,
      dedicated keys; keep secrets in environment variables, never argv or
      this checklist. Record the creation tx, address, deployer, date, deliver
      tx, burn tx, and the empty-slot proof. The receive path does not log the
      burn, so recover its txid from chain state with
      `scripts/evm-burn-txid.sh` — the same lookup `scripts/anvil_e2e.sh` runs
      locally. A receipt that names the transaction beats a note that explains
      why it cannot.
- [ ] **Save both estimates:** before deploy, run
      `spore contract estimate -rpc https://mainnet.base.org -from 0x<deployer>`;
      after deploy, re-run with `-mailbox 0x<address>` and the same `-from`.
      Keep the output used for the funding decision. It is a live snapshot,
      not a price promise; burn may be the labeled conservative fallback.

## 1. Tree state and pre-push gates

- [ ] `git status` clean; inspect branch and HEAD before release operations.
      Do not overwrite, stage, or commit unrelated work.
- [ ] `main == origin/main`; all deployment evidence is real and the §3
      receipt is ready to publish.
- [ ] `go test ./internal/evm ./cmd/spore` passes on the final post-flip
      commit (registry populated and Patches 6–7 present). The referee includes:
      `TestShippedMailboxDefaultsCarryReceipts`,
      `TestDocClaimsMatchRegistryState`, and
      `TestReleasePrepProseDrainedAfterFlip`.
- [ ] Full pre-push gates pass (`scripts/gates.sh` / lefthook) on the exact
      main commit before tagging. Those gates are the only gate now: the
      repository has no GitHub Actions workflows, so nothing runs on a push
      except what you run yourself — use the full run, not `--quick`.
- [ ] **Deep fuzz pre-flight:** `bash scripts/fuzz-smoke.sh --deep` (60s per
      target, about nine minutes) on the release candidate. It is deliberately
      not part of the pre-push gate. A crash writes its input under the
      target's `testdata/fuzz/`; commit that as the regression seed. Then run
      `bash scripts/fuzz-corpus.sh --save`, which stores what the deep run
      found and minimizes the store in the same pass — otherwise every release
      inherits every input the last one generated, and the corpus stops being
      something a reviewer can read. If the soak (`scripts/fuzz-soak.sh`) is
      scheduled on the release host, its last report is this line's evidence:
      attach `bash scripts/fuzz-soak.sh --status` instead of running a pass by
      hand.
